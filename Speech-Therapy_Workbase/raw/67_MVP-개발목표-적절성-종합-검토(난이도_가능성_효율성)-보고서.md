## 1. 개발 속도 관점 (Time-to-Market 최적화)
**목표:** MVP 단계에서의 과도한 시간 소요 및 디버깅 지옥 회피

### 🟢 긍정 요소 (빠른 개발 가능)
* **Next.js + Supabase 조합:** AI 코딩 어시스턴트(Cursor 등)가 가장 방대한 학습 데이터를 가진 스택입니다. 로그인, 회원가입, 미션 데이터 CRUD, 대시보드 UI 등은 프롬프트만으로 하루 이틀 안에 완성 가능합니다.

### 🔴 리스크 및 조정 권장 사항 (Descope 제안)
바이브 코딩의 맹점은 "AI가 짜준 코드가 동작하지 않을 때, 브라우저/OS 단의 하위 레벨 지식이 없으면 디버깅에 수십 일이 소모된다"는 것입니다.
1. **[조정 제안 1] 실시간 오디오 처리 우회 (MVP 극초기):** 
   * 처음부터 Web Audio API(마이크 권한, 실시간 스트리밍)에 매달리면 진도가 나가지 않습니다. 
   * **MVP 1주차 목표:** 음성 스트리밍 대신 **"녹음된 음성 파일(mp3) 업로드"** 또는 **"원장/교사의 텍스트 평가 입력"** 방식으로 시스템 코어(진단-미션-보상 사이클)를 먼저 관통시키세요. 마이크 연동은 가장 마지막에 붙여야 합니다.
2. **[조정 제안 2] 네이티브 앱 배포 보류:** 
   * PWA(웹앱)로 브라우저에서 먼저 테스트하세요. Capacitor를 이용한 iOS/Android 스토어 심사 및 배포는 인증서, 빌드 에러 등 AI가 해결해주지 못하는 물리적 시간 소요가 큽니다.
3. **[조정 제안 3] Phase 2 (Zero-touch) 전면 보류:** 
   * Web Worker 기반의 백그라운드 VAD(발화 감지)는 입문자가 AI 도움만으로 디버깅하기에는 브라우저 탭 백그라운드 제한(Throttling) 등 변수가 너무 많아 1개월 내 달성이 불가능에 가깝습니다.

## 2. 외부 연동 목표와 기술 스택 검토
**목표:** 복잡성 최소화 및 외부 종속성 리스크 관리

### 1) AI / LLM 연동 (Gemini + Vercel AI SDK)
* **적절성 (최상):** 별도의 파이썬 서버(LangChain 등)를 구축하지 않고 프론트엔드 환경에서 직접 LLM을 호출하는 V05의 아키텍처는 인프라 관리 포인트를 0으로 만듭니다. 오픈소스 모델을 직접 호스팅하는 대신 Managed API(Gemini)를 쓰는 것은 비용과 속도 면에서 완벽한 선택입니다.

### 2) STT (음성 인식) 엔진 선택 리스크
* **오픈소스(Whisper) vs Managed(Google STT API):**
  * 직접 Whisper 모델을 서버에 올리는 것은 배포 복잡도와 GPU 인프라 비용(월 수십만 원)을 유발하므로 절대 피해야 합니다.
  * **조정 권장:** 무조건 API 호출 단위로 과금되는 **Google Cloud Speech-to-Text API** 또는 **OpenAI Whisper API**를 사용하세요.

### 3) 카카오 알림톡 및 키즈노트 API 연동 리스크
* **리스크 (상):** 카카오 알림톡은 템플릿 사전 심사가 필요하며 며칠이 소요됩니다. 특히 키즈노트 API는 B2B 공식 제휴가 없으면 API Key 발급이 막혀 있을 확률이 높습니다.
* **조정 권장:** MVP 단계에서는 카카오 알림톡 대신 **일반 Web Link(클립보드 복사) 공유**로 대체하고, 키즈노트 연동은 **알림장 텍스트 클립보드 자동 복사** UI로 우회하여 기술적 종속성을 즉각 제거해야 합니다.
